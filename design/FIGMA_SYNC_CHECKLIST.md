# 网页原型同步到 Figma 的核对清单

## 以浏览器最终画面为准

1. 固定版本、页面、会员状态、Tab、套餐和协议勾选状态；记录对应的 Figma Frame。
2. 等页面脚本运行完，再读取目标区域的 DOM、文本、计算样式、尺寸和素材。不能只读 HTML 模板：`src/workspace-ui.js` 会重写付费页协议，`src/revision-review.js` 也可能更新购买文案。
3. 记录动态文本的实际值，并标出字体、字号、字重、行高、颜色、渐变、间距和换行位置。不得凭截图重新输入文案。
4. 对每个文本同时检查承载布局的父节点和最终显示文字的叶子节点。编辑器可能插入 `.model-editable-text`；父节点字号不一定是实际字形字号。记录两者的计算样式与边界，并按叶子节点最终渲染结果制作。

## 在 Figma 中保留结构

1. 本次新建或编辑的文本图层设置 `textAlignVertical = 'CENTER'`（Align middle），完成文本框尺寸后再检查一次；源设计明确要求顶部对齐的多行正文除外。
2. 使用仓库中的原始图形素材；有异形轮廓时不得以圆角矩形代替。
3. 按 DOM 的父子关系建立图层。勾选框与协议标签应在同一个水平自动布局容器中；协议链接保留独立的绿色文字样式。
4. 若源字体在 Figma 中不可用，记录替代字体，并把这项标成视觉差异，不声称像素级一致。

## 交付前逐项检查

1. 在相同的 390 × 1356 逻辑尺寸下，对照浏览器与 Figma 截图。
2. 比对每段文字的字面内容、换行、字号和颜色；比对每个控件的边界、对齐、填充和素材。
3. 修复可见差异后再截一次图。仅在核对通过的范围内说明“已还原”，明确尚未核对或受字体限制的部分。
4. 逐项列出源图中可见的装饰文字、图标、水印与细线，并在 Figma 截图中核对其存在、大小、位置和透明度。只完成 DOM 抽取或只看一次整页截图，都不能算通过。

## 当前付费页的易错点

- 默认状态为 VIP / Free / 连续包年，购买按钮显示“微信支付88元”。
- 按钮在网页中的计算字号为 16.6px、字重 500，背景是从 `#feeba0` 到 `#ffbd28` 的横向渐变。
- 连续套餐协议由 `bindPaymentAgreement()` 运行时生成：12px 未选中勾选框、5px 间距、19px 行高、绿色协议链接，后接动态扣费日期。
- 三个 Tab 使用 `assets/vip-tab-left.png`、`vip-tab-middle.png`、`vip-tab-right.png` 的异形轮廓。
